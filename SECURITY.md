# Security Policy

## Supported Versions

We support security updates for the latest released version of `rcal`.

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1   | :x:                |

---

## 🔒 Reporting a Vulnerability

The safety of user data, calendar credentials, and sync tokens is critically important to us.

If you discover a security vulnerability in `rcal`, please **do NOT report it in public GitHub Issues**. Instead, follow these steps:

1. **GitHub Security Advisory**: Use the private security advisory feature on GitHub under **Security > Advisories > Report a vulnerability**.
2. **Email**: If you prefer email, reach out privately to the maintainers at the contact email listed on the author's GitHub profile.

### What to Include in Your Report:

* A clear description of the vulnerability.
* Steps or a proof-of-concept (PoC) to reproduce the issue.
* Potential impact on user credentials, OAuth tokens, or local databases.
* Any potential mitigations or suggested fixes.

### Response Timeline:

* **Initial Acknowledgement**: Within 48 hours.
* **Assessment & Fix**: We will triage the vulnerability and prepare a patch as quickly as possible.
* **Disclosure**: A public release and advisory will be coordinated after a fix is verified.
